# Application versioning

Release metadata lives in the product **Version manager** (`/versions`) and in `packages/shared/src/release-history.json`.

- **Current version:** stored in `.idrac-version-state.json` and `packages/shared/src/version.ts` (`APP_VERSION`).
- **Release catalog:** `packages/shared/src/release-history.json` (major/minor/patch entries with core implementation notes).
- **Initial release:** v1.0.0
- **Automation:** each git commit with staged changes runs `scripts/version-track.mjs` (via the `pre-commit` hook installed by `pnpm prepare`).
- **Bump rule:** after **10** tracked changes, the **PATCH** segment increments (e.g. v1.0.0 → v1.0.1) and the change counter resets. Patch bumps update `APP_VERSION` and package versions only—they are **not** appended to `release-history.json`.
- **Version manager page:** lists **major** and **minor** milestones only; routine patch/fix builds are omitted from the public log.
- **Minor/major releases:** edit `release-history.json` manually with accurate titles and core implementation bullets, then bump `version` in `.idrac-version-state.json` and run `pnpm version:track` or sync package versions consistently.
- **Manual run:** `pnpm version:track`
- **Displayed in:** web footer (links to `/versions`), version manager page, API `GET /api/` and `GET /api/health`.

Do not edit `packages/shared/src/version.ts` by hand; it is regenerated by the version script.

When publishing a minor or major release, update the corresponding section in docs (**Product Versions**) if the release line theme changed.
